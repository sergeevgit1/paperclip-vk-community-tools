# Проектирование Callback API для VK Community Tools

## Цель

Добавить к плагину VK Community Tools полноценное подключение Callback API без изменений ядра Paperclip:

- показывать в настройках готовый публичный URL для ВКонтакте;
- корректно отвечать на запрос подтверждения VK чистым текстом;
- принимать тестовые и рабочие Callback-события;
- показывать оператору результат последнего входящего запроса;
- максимально перевести пользовательский интерфейс и описания инструментов на русский язык.

## Ограничения

- Ядро Paperclip не изменяется.
- Штатный webhook-маршрут Paperclip нельзя отдавать ВКонтакте напрямую: он отвечает JSON, а VK требует чистую строку `confirmation_code` или `ok`.
- Публичная точка входа размещается в отдельном контейнере на том же сервере.
- Публичный домен: `https://vk.openser.ru`.
- DNS и SSL настраиваются оператором вручную.
- Токены VK не передаются в URL, логи или интерфейс.

## Архитектура

```text
VK Callback API
    |
    | POST https://vk.openser.ru/callback/<group_id>?confirmation=<code>&secret=<secret>
    v
Отдельный Callback-шлюз
    |
    | POST /api/plugins/zaruba.vk-community-tools/webhooks/vk-callback
    v
Paperclip -> worker VK Community Tools -> журнал событий / агенты
```

Callback-шлюз представляет собой отдельный минимальный HTTP-сервис на Node.js без сторонних зависимостей. Он запускается отдельным контейнером и не модифицирует Paperclip.

## Публичный URL

Формат:

```text
https://vk.openser.ru/callback/<group_id>?confirmation=<confirmation_code>&secret=<callback_secret>
```

- `<group_id>` — числовой идентификатор сообщества.
- `<confirmation_code>` — строка подтверждения из настроек Callback API VK.
- `<callback_secret>` — отдельный секрет Callback API, не токен доступа VK.

Плагин формирует готовый URL в интерфейсе. Рядом отображается кнопка копирования.

## Обработка запросов

### Запрос подтверждения

При payload:

```json
{
  "type": "confirmation",
  "group_id": 123456
}
```

Шлюз:

1. проверяет, что `group_id` из тела совпадает с идентификатором в URL;
2. проверяет секрет, если он указан;
3. записывает статус последнего запроса;
4. возвращает чистый текст `confirmation_code` с HTTP 200.

### Обычное событие

Шлюз:

1. проверяет `group_id` и секрет;
2. пересылает исходный JSON в штатный webhook плагина Paperclip;
3. возвращает VK чистый текст `ok` только после успешной передачи;
4. при ошибке возвращает HTTP 502, чтобы VK повторил доставку;
5. записывает безопасный статус без тела сообщения, токенов и секрета.

## Диагностика

Шлюз предоставляет read-only endpoint состояния для UI плагина. Состояние содержит только:

- группу;
- тип последнего события;
- время приёма;
- результат передачи в Paperclip;
- безопасное сообщение об ошибке;
- признак успешного подтверждения.

Секрет, код подтверждения, payload пользователя и заголовки авторизации не возвращаются.

UI показывает:

- «Ожидается тестовый запрос от ВКонтакте»;
- «Тестовый запрос успешно получен»;
- время последнего Callback-запроса;
- тип последнего события;
- результат передачи в Paperclip.

## Интерфейс

В разделе «Callback API» отображаются:

1. готовый URL;
2. кнопка «Скопировать»;
3. краткая инструкция:
   - открыть настройки сообщества VK;
   - перейти в «Работа с API -> Callback API»;
   - вставить адрес;
   - выбрать нужные типы событий;
   - нажать «Подтвердить»;
4. статус последней проверки;
5. кнопка ручного обновления статуса.

Callback-поля показываются только при выбранном транспорте «Callback API».

## Русификация

Переводятся пользовательские строки:

- заголовки и подсказки настроек;
- сообщения кнопок, уведомлений и ошибок;
- статусы транспорта и журнала;
- названия и описания 23 инструментов плагина;
- описания параметров инструментов;
- пользовательские сообщения виджета.

Не переводятся стабильные технические идентификаторы:

- имена инструментов (`vk_wall_post` и другие);
- ключи JSON;
- типы событий VK (`message_new`, `wall_reply_new`);
- значения транспорта (`callback`, `long_poll`, `disabled`).

## Безопасность

- URL не содержит токенов VK.
- Callback-секрет сравнивается постоянным по времени способом.
- Секрет и код подтверждения маскируются в логах.
- Максимальный размер тела ограничен.
- Принимается только JSON через POST.
- `group_id` проверяется до пересылки.
- Шлюз не предоставляет произвольный прокси и пересылает запросы только во внутренний Paperclip endpoint.
- Статус диагностики не содержит пользовательский payload.

## Контейнер

В репозитории добавляется каталог `callback-gateway/`:

- `server.mjs` — HTTP-сервис на стандартной библиотеке Node.js;
- `Dockerfile` — минимальный образ Node.js;
- `README.md` — переменные окружения и запуск;
- тесты протокола.

Переменные окружения:

- `PORT` — внутренний порт сервиса;
- `PAPERCLIP_WEBHOOK_URL` — внутренний URL штатного webhook плагина;
- `PUBLIC_BASE_URL=https://vk.openser.ru`;
- `MAX_BODY_BYTES` — ограничение тела.

## Проверки

### Автоматические

1. confirmation возвращает чистый код без JSON и кавычек;
2. обычное событие после успешной пересылки возвращает `ok`;
3. ошибка Paperclip возвращает 502;
4. неверный `group_id` отклоняется;
5. неверный секрет отклоняется;
6. превышение размера тела отклоняется;
7. диагностический endpoint не раскрывает секреты и payload;
8. UI формирует правильный URL;
9. UI отображает ожидание, успех и ошибку;
10. инструментальные описания локализованы.

### Production-проверка

1. Проверить отсутствие активных запусков агентов.
2. Собрать и проверить плагин и Callback-шлюз.
3. Запустить шлюз без публикации DNS.
4. Отправить локальный запрос `confirmation` и подтвердить чистый ответ.
5. Отправить локальное тестовое событие и подтвердить запись в Paperclip.
6. После ручной настройки DNS/SSL проверить публичный URL.
7. Выполнить реальное подтверждение в интерфейсе VK.
8. Убедиться, что UI показал успешный тестовый запрос.

## Откат

- Остановить отдельный Callback-контейнер.
- Вернуть предыдущую версию плагина.
- Выбрать Bots Long Poll в настройках.
- Ядро Paperclip не меняется, поэтому его откат не требуется.
